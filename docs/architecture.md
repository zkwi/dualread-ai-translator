# 架构说明

DualRead 是一个无构建步骤的 Chrome Manifest V3 扩展。运行时由原生 JavaScript、Chrome Extension API 和 OpenAI-compatible Chat Completions API 组成，没有项目自有服务器。

## 文件职责

```text
shared.js       共享默认值、规范化、缓存 key、语言和布局纯函数
study.js        学习模式的级别、提示词、输出解析、高亮定位和复读检测（纯函数）
background.js   Chrome 生命周期、标签页控制、API 请求、SSE 解析和缓存
content.js      页面候选发现、逐段队列、译文插入和结构感知布局
popup.*         当前页面的开始/停止、显示方式、状态摘要和学习模式入口
options.*       精简的连接/语言/阅读设置，以及折叠的高级覆盖与维护入口
reader.*        学习模式阅读页：流式渲染课程、词汇释义弹层、段落对照
_locales/       四种界面语言文案
test/           共享/后台/学习模式单测、浏览器 fixture、扩展 smoke 和真实页面样本
```

项目刻意保持少文件、无打包器。只有职责出现可独立复用或测试的真实需求时才继续拆分。

## 正文翻译主链路

1. content script 在当前视口及附近发现可读文本块，并按正文/视口优先级排序。
2. 每个段落独立进入并发受限队列，默认同时运行 2 个请求。
3. content script 通过 `llm-translation-stream` Port 发送单段任务。
4. background 先查段落缓存；未命中则请求纯文本 SSE。
5. 每个 `delta` 立即更新页面中的“翻译中”占位，完成后保存缓存。
6. 端点明确不支持流式时，该 API/模型在当前 service worker 生命周期内降级为单段非流式请求。
7. SSE 中的非 JSON 心跳、注释行和末尾截断块被逐行跳过，单个坏块不会终止整段翻译。
8. 停止翻译或视口跳转会通过 Port 发送 `cancel`；流式和非流式请求都接收该取消信号，取消不会被报成超时。

请求发出前先校验 API Key、模型和 API 地址协议，地址非 http/https 时给出明确提示，而不是抛出底层 `Invalid URL`。

`maxConcurrentBatches` 是历史存储键，当前语义为“同时翻译段落数”。`batchSize` 和 `maxCharsPerBatch` 仅为旧存储及兼容代码保留，不参与正文调度。

## 学习模式链路

1. 弹窗按钮或右键菜单调用 `openStudyMode`：先校验 API 配置，再注入脚本读取页面文字。选区够长时只取选区：对选区右键 40 个字符即可，弹窗按钮要 80 个字符，避免把之前随手选中的词当成正文。否则取最长且有布局的 `main`/`article` 区域（至少 1000 字符），没有时退回整页 `innerText`。读取前用行内样式临时隐藏已插入的译文和扩展浮层，避免混进原文。
2. 本地先判断是否以英文为主，再把原文存入 `chrome.storage.session`（最多保留最近 8 篇，浏览器关闭即清除），然后在原标签旁打开 `reader.html?source=<id>`。
3. 阅读页通过 `llm-study-stream` Port 发送 `start`（级别、是否跳过缓存）。background 在行边界把原文截到 12000 字符，先查课程缓存，未命中再发一次流式请求：`max_tokens` 为 12000（DeepSeek 不传时会在 8192 处截断），沿用连接测试探测到的 Thinking 参数；服务商明确拒绝 `max_tokens`、Thinking 字段或流式时，去掉对应参数重试。
4. 输出依次用 `@@TITLE`、`@@ARTICLE`、`@@KEY`、`@@VOCAB`、`@@TRANSLATION`、`@@GRAMMAR`、`@@SENTENCES`、`@@PARAGRAPHS` 分段：重点是原文标注，词汇表条目最多，每条带 `[短义]` 用作正文旁注；译文紧随其后，段末“译”按钮能尽早可用；语法、长难句各 1-2 条，`@@PARAGRAPHS` 只是 2-5 行文章脉络。正文只照抄原文，段落以 `¶n` 编号；高亮不靠模型在正文里打标记，而是由 `study.js` 按词汇表和关键句在本地定位，原形词条可匹配正文里的变形。译文和脉络按 `¶n` 对齐。
5. 增量攒 80ms 再发给阅读页。超时按“多久没收到新数据”计算；检测到复读（同一短片段连续重复）就中止并裁掉重复部分。课程须带 `@@END`，且正文和译文段号逐段对应，才存入 `llm_translator_cache:study:` 前缀；读取缓存时也会复核完整性。未完整结束的课程保留已生成内容并提示重试。缓存最多 20 份，设置页“清除缓存”会一并删除。
6. 切换级别或重新生成会取消上一请求；阅读页在生成期间每 20 秒发一次 ping，避免 service worker 空闲回收打断流式请求。
7. 阅读页每 120ms 合并渲染一次，HTML 没变的区域不写 DOM：笔记流式输出时正文保持不动，读者选中的文字和键盘焦点不会被冲掉。段落译文只由段末“译”按钮展开或收起，点击原文不会触发；切换时直接修改对应译文节点的 `hidden`，展开状态记在 `revealed` 里，之后重绘生成的 HTML 与之一致。切换级别或重新生成时，段落译文和全文翻译都恢复收起。

设计取舍：

- 用新标签页而不是页面浮层：不受原站 CSS、重渲染和滚动锁定影响，课程也能保留和刷新。
- 不单独设置学习模式模型：Thinking 自动探测按“API 地址 + 模型”保存，换模型后不会发送关闭思考的参数，DeepSeek 等默认思考的模型会明显变慢。需要更准的讲解时直接把连接模型换成更强的模型并重新测试 API。
- 只发域名不发完整 URL：路径和查询参数可能带会话令牌，对提取正文也没有帮助。

## 页面候选与布局

候选发现采用“快速视口采样 + 有界补扫”，不默认遍历整页。通用规则会跳过导航、广告、表单、弹窗、媒体错误层和低价值元数据。

译文插入前会识别 Block、Flex、Grid、列表、裁剪预览和 Web Component Slot。适配优先基于 DOM 结构和计算样式；只有无法用通用结构表达的平台语义才保留少量站点规则。

## Thinking 控制能力

自动模式不根据服务商、URL 或模型名称猜测参数。

- 点击“测试 API”时，background 依次尝试已有的通用 Thinking 控制形状。
- 只有 400/422 且明确指出 Thinking 字段不支持时才继续下一个候选。
- 鉴权、限流、模型、网络、超时和服务端错误立即停止。
- 后台返回首个成功策略与规范化的 API/模型检测键，由设置页确认连接在测试期间未变后保存到本地存储，避免旧测试覆盖新配置的探测结果。
- API 地址或模型变化后检测键不匹配，运行请求不发送额外 Thinking 参数，直到重新测试。
- 手动策略直接使用用户选择，不进行候选探测。

OpenAI-compatible 协议无法判断服务商是否静默忽略未知字段，因此自动结果表示“连接测试成功采用的参数”，不是对模型内部推理状态的证明。

## 缓存与预算

- 缓存按段落保存，key 包含 API 地址、模型、语言、提示词和原文。
- 缓存 TTL、最大条目数、每页请求数和字符数都有上限。
- 低层预算与缓存上限使用共享默认值；设置页不再暴露这些调优项，也不会覆盖旧存储中的自定义值。
- 停止/清除或切换运行时会取消旧请求，并忽略旧 run ID 的返回。

## 兼容边界

`translate_batch`、批量 JSON 提示词和修复解析器只兼容旧消息及回归测试。网页正文从 0.7.0 起不再调用它们。删除兼容层前应先确认没有已注入的旧 content script 或外部调用仍依赖该消息。
